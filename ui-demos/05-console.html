帮我看看 src/llm/openai.ts —— 流式解析在断线重连之后，会把已经吐过的那一段再重复输出一次。找下根因。

两条线索：
1. 重试循环是否复用了上一次的 partial text buffer
2. 断点恢复时 lastEmittedIndex 是否被重置为 0

export async function* streamChat(req: ChatRequest, signal?: AbortSignal) {
  let emitted = "";
  let retries = 0;
  while (true) {
    try {
      const stream = await client.chat.completions.create({ ...req, stream: true });
      for await (const chunk of stream) {
        const delta = chunk.choices[0]?.delta?.content ?? "";
        if (!delta) continue;
        emitted += delta;          // ← 重连后 emitted 未重置
        yield { type: "delta", text: delta };
      }
      return;
    } catch (err) {
      if (++retries > 3) throw err;
    }
  }
}

根因在重试循环里：emitted 是循环外声明的，重连成功后会从上次断点继续累加，但上层把它当作「本轮全部产出」重新回填了一遍。

修法

把「已发出去的长度」当锚点，重连后只 yield 增量：

catch (err) {
  if (++retries > 3) throw err;
  emitted = emitted.slice(0, lastYielded);   // 回退到已确认位置
}
  • lastYielded 在每次 yield 之后同步
  • 退避重试保留，但不再污染文本流
anthropic.ts 里有同样的形状，建议一起改。
