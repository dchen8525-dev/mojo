# 记忆召回选择器

## 状态

- 2026-10-22 落地。本文定义长时记忆在提示词预算之外如何按需召回。

## 背景

`renderMemory` 把项目级 `.node-agent/memory.md` 与用户级 `~/.node-agent/memory.md`
注入系统提示词，每个来源最多 12,000 字符。超出预算时旧实现直接保留文件尾部，较早的
决策与坑会永久消失。本功能让这些被裁掉的条目仍能在相关请求里到达模型。

## 稳定部分：只注入最新条目

- 记忆文件按 2-6 级 ATX 标题（`##` …）切分为条目；标题与正文保持在一起，代码围栏内的
  `##` 行不切分。首个标题之前的内容作为一个无标题条目。
- 每个来源从**最新条目向前**累加，直到 12,000 字符预算；只保留完整条目，旧条目整体裁掉。
- 最新条目本身就超过预算时，保留它的尾部并加 `…`，避免记忆完全消失；更早的条目仍可被
  召回。若整个文件只有一个超大条目，则没有可召回的裁剪内容。
- 有内容被裁掉时，系统提示词里的记忆前言增加“Older entries were trimmed here and are
  recalled per request when relevant.”，并在块首加 `…`。
- 未超预算时输出与旧版一致：文件内容原样注入，不出现任何召回提示。

稳定部分的文本只随文件内容变化，因此同一会话内不会破坏 provider 的前缀缓存。

## 召回部分：当轮词面选择

- 只在**被稳定部分裁掉的条目**中挑选；已经注入的内容不会重复。未超预算时召回恒为空。
- 查询使用当前用户输入。分词规则：
  - CJK（中日韩）连续文本切成二元组（单字文本保留单字），如 `登录超时` →
    `登录`、`录超`、`超时`；
  - 拉丁字母/数字按整词匹配（长度 ≥ 2），过滤常见英文停用词。
- 打分：标题命中按词长 ×2，正文命中按词长 ×1；总分低于 2 不召回。
- 按分数降序、同分时较新的条目优先；最多 3 条、合计 2,400 字符。第一条本身超限时截断到
  预算并追加 `…`，后续条目不再回填。
- 选中条目以 `<system-reminder event="RecalledMemory">` 追加到**当轮用户消息**，内部为
  `<memory_entry source="..." heading="...">…</memory_entry>`。这是逐请求的提示，不写入
  记忆文件，也不改变系统提示词缓存。
- 纯词面、确定性、零额外模型请求；读取失败或没有匹配时静默跳过，绝不影响回合。

## 非目标

- 不做 LLM 语义选择、embedding/向量索引、外部知识库、超时重试或关键词 fallback 之外的
  第二套机制。
- 不改动记忆写入协议：压缩交接摘要仍由 `appendMemoryNote` 追加到项目记忆文件。
- 不把召回内容回写为记忆，也不增加单独的持久化状态。

## 代码与测试

- `src/memory.ts`：`splitSections`、预算选择、`selectMemoryEntries`、`recallMemory`；
  `renderMemory` 复用同一加载逻辑。
- `src/agent.ts`：`chat()` 在当前用户输入上调用 `recallMemory`，命中时追加
  `RecalledMemory` 系统提醒。
- 测试：`tests/memory.test.ts`（预算标记、超预算召回、CJK 二元组、用户级记忆、打分与
  截断）、`tests/agent.test.ts`（注入到当轮用户消息）。
